微分音のグリモワール 第Ⅶ部 実践

第Ⅶ部 実践　─　1

調律ファイル

直感レイヤー

理論から制作へ。最初の実務は「音律をコンピュータに伝える」ことです。
その共通語が Scala 形式、拡張子 .scl（音階の中身）と .kbm（鍵盤への割り当て）の2種のセット、および Anamark tuning ファイル.tunがあり、微分音対応ソフトのほとんどがこれらいずれかを読みます。

.scl ファイル ── 音階そのもの

.scl は音階の音程を、基準（1/1）からのセント値または比で列挙するテキストです。31edo なら「オクターブを31等分」なので、各音は \(k \times \frac{1200}{31}\) セント。構造はこうです：

! 31edo.scl
!
31-edo
 31
!
 38.70968
 77.41935
 116.12903
 ... （中略：4〜30番目）
 1161.29032
 2/1

読み方：感嘆符 ! で始まる行はコメント。最初の非コメント行が説明文、次が音数（31）。以降が各音の音程で、小数点を含めばセント、含めば比（3/2 など）として解釈されます。慣例として最後はオクターブ 2/1（＝1200¢）で閉じ、起点の 0.0 は書きません（1/1 は暗黙）。つまり31行の音程データが並びます。等分音律は「1200/31 の倍数を31個」書くだけ。
下のジェネレータで実物を作れます。

edo .scl ジェネレータ（お試し）


      
生成された内容をテキストエディタに貼り、31edo.scl のような名前で保存すれば、そのまま各種ソフトに読み込めます。音源基準（C4＝261.6255653 Hz など）は .scl ではなく次の .kbm か、ソフト側の設定で与えます。

    


    
.kbm ファイル ── 鍵盤への割り当て


    
.scl は音階の「形」だけを定め、どの鍵盤キーをどの音に、どの周波数を基準に割り当てるかは .kbm（keyboard mapping）が担います。
31音を12鍵の物理鍵盤やMIDIにどう載せるかはこのファイル次第で、線形（1鍵1音で上へ）にも、後述のチャンネル分割（Ⅶ-6）にもできます。基準周波数の指定もここで行います：


    
! 基準：MIDI 60 (C) を 261.6 Hz 
! Size of map
12
! First / last MIDI note
0
127
! Middle note
60
! Reference note / freq
60
261.6255653
! Octave degree (scl の何番目でオクターブか)
12


    
A4＝440 Hz を基準にしたい場合は、reference note を 69、freq を 440.0 とします。ただし多くのプラグインは基準周波数を独自 UI で持つため、.kbm を省いて .scl だけ渡す運用も一般的です。


    
AnaMark .tun ファイル ── もうひとつの標準


    
.scl/.kbm と並んで広く使われるもう一つの調律ファイル形式が、AnaMark の .tun（TUN／AnaMark tuning file）です。もともと AnaMark シンセのために作られ、その後 VST 界でデファクトスタンダードのひとつになりました。
.scl が「音階の相対構造」と「鍵盤割り当て」を2ファイルに分けるのに対し、.tun は128個の MIDI ノートすべてに絶対周波数をセントで直接列挙するスタイルで、1個のファイルで「どのキーが何 Hz か」が完全に決まる自己完結型です。テキスト形式で、おおむね次の構造を持ちます：


    
; AnaMark tuning file (.tun)
[Tuning]
note 0=（MIDI 0 のセント値）
note 1=...
... note 127 まで128行
[Exact Tuning]
basefreq=261.6255653   ; 基準周波数

basefreq=261.6255653   ; 基準周波数


    
.tun の長所は自己完結性で、128鍵の絶対音高が1ファイルに収まるので、鍵盤割り当ての解釈違い（.kbm の設定ミス）による事故が起きにくいものです。
多くの VST シンセ（Serum 2、 Vital、 UVI Falconシリーズ、 Omnisphere 2、 Keyscapeなど）が .tun を読み込めます。短所は、128鍵を全部書き下すぶん「音階の構造」が読み取りにくいことと、フォーマットにバージョン差（AnaMark TUN v0/v1/v2）があり実装ごとに解釈が微妙に異なる場合があること。構造を編集・共有するなら .scl、特定の音源に確実に流し込むなら .tun、と使い分けるのもいいでしょう。


Scale Workshop


      
Scale Workshop は微分音音楽の先駆者 Sevish 氏の作成した音律ファイルを生成できるウェブアプリです。
.scl と .tun の両方を書き出せるので、設計は Scale Workshop で行い、送り先の音源が要求する形式でエクスポートする、という導線が今日の定番です。音源の対応状況は Xenharmonic wiki の対応プラグイン一覧が随時更新しています。

      精密レイヤー ── Scala エコシステムと相互運用
      

        
Scala は単なるファイル形式ではなく、Op de Coul による同名のフリーソフト（音律の計算・分析・変換を行う老舗ツール）でもあり、その付属の scale archive には5000超の音律 .scl が収録されています。ミーントーン、各歴史的調律、世界の民族音律、そして本書で扱った rank-2 音律の MOS の多くが既製ファイルとして手に入ります。31edo を自作せずとも 31.scl が最初から入っています。

        
相互運用の注意を三点。
（1）比か小数か：
.scl は行に小数点があればセント、なければ比と解釈します。700.0（700¢）と 700（700/1 という比＝とてつもない高音）はまったく別物で、セントを書くときは700.のように必ず小数点を付けます。
（2）1/1 を書かない：
起点は暗黙で、列挙するのは2番目の音から。31edo なら 38.7¢ から 1200¢（＝2/1）までの31行。
（3）形式の使い分け：
MTS-ESP・Vital・Scale Workshop などは .scl/.kbm や.tunを両方読めるものがあります。とはいえ.tunは音高を絶対的に正しくもち、最も事故が少ないので、まず scl.で構造を持ち、必要に応じて Scale Workshop で変換を行い、送り先に合わせて書き出すのが今日の定番です。

      

    


    

      この節の要点
      
      Scala 形式が音律の共通語。
.scl＝音階の中身をそのままセントで書いている。小数点ありでセント・なしで比、1/1 は省略、末尾が period。
.kbm＝鍵盤割り当てと基準周波数。
並ぶ標準に AnaMark .tun（128鍵の絶対音高を列挙）がある。
